1. Executive Summary & Core Philosophy

Conventional personal finance platforms categorize past historical spending (telling users what went wrong after the month is over). DayBudget fundamentally shifts this paradigm into an active, day-by-day allowance tracker. It divides available discretionary income evenly across the days of the month, continuously recalculating targets in real time based on active spending habits, carry-over surpluses, and extreme overspend events.

Daily Allowance = (Monthly Income − Fixed Obligations − Monthly Savings Goal) ÷ Days in Month

2. System Architecture

Frontend Architecture

Built on Next.js 14 App Router with TypeScript, Tailwind CSS, and Recharts. Implements responsive layouts across desktop, tablet, and mobile (320px–1920px), complete with an optimistic UI toast notification system and theme toggling (Dark/Light mode).

Backend & Cloud Storage

Leverages Next.js Route Handlers coupled with Prisma ORM and cloud-hosted Supabase PostgreSQL. Uses connection pooling (`pgbouncer`), strict schema constraints, bcrypt password hashing, and signed HTTP-only JWT session cookies.

3. Key Modules & Functional Overview

A. Dynamic Budget Calculation Engine

  • Month-Length Awareness: Handles 28, 29, 30, and 31-day months dynamically using standard calendar projection.
  • Surplus Mode: When spending is below the daily budget, unspent money carries over to boost future days or can be swept directly to savings goals.
  • Deficit Recoupment: Overspending on any single day distributes the deficit across remaining days to keep monthly totals in check.
  • Emergency Shield: Allows extreme unexpected costs to be logged with justification without penalizing daily budgets.

4. Database Schema Specification (Supabase PostgreSQL)

The relational database schema is structured to ensure cascading integrity, indexed queries, and zero data leakage:

  • User: Unique UUID, encrypted password hash, ISO currency code, surplus mode preference.
  • BudgetProfile: 1:1 relation with User; records monthly baseline income, savings percentage, and active month/year.
  • FixedExpense: 1:N recurring bills (Rent, EMI, Utilities) with scheduled due days.
  • Expense: Granular daily spending records containing timestamps, categories, payment methods, and emergency tags.
  • BankAccount & BankTransaction: Accounts holding masked account numbers, provider types, and linked transactions.
  • SavingsGoal: Milestone tracking target amounts, current saved amounts, and completion flags.
  • Notification: System-generated reminders including daily morning greetings and sync audits.

5. Security & Production Hardening

  • Rate Limiting: In-memory sliding window rate-limiter protects sensitive endpoints (`/api/auth/login`, `/api/auth/register`, `/api/feedback`) from brute-force attempts.
  • Input Sanitization: Null-byte stripping, character limit enforcement, and HTML tag sanitization prevent XSS attacks.
  • Safe Credential Handling: Passwords hashed via bcrypt (salt factor 10). Session tokens stored in secure, SameSite, HTTP-only cookies.
  • Database Security: Configured via environment variables; `.gitignore` strictly protects `.env` files from leaking into Git.

7. Deployment Instructions (Vercel)

  1. Push the repository to GitHub: git push -u origin main
  2. Import likhithgp2006/DayBudget in the Vercel Dashboard.
  3. Configure the four production environment variables:
    • DATABASE_URL: Supabase connection pooler string.
    • DIRECT_URL: Supabase direct PostgreSQL string.
    • JWT_SECRET: Cryptographic token secret.
    • NEXT_PUBLIC_APP_URL: Live deployed domain URL.
  4. Deploy! The built-in postinstall: prisma generate hook ensures zero-downtime client generation.
